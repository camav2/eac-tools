Screen Architecture

All tools use the same screen system. .screen is hidden by default; .screen.active sets display:flex. Navigation is driven by showScreen(id).

1
Intro
Entry point. Always first. Dark navy background.
#screen-intro
↓ startTool()
2
Questions
Sequential panels. One .question-panel.active at a time. Sticky header + sticky footer.
#screen-questions
↓ nextQuestion() — after final Q
3
Email Gate
Skipped if eacUser is set (already authenticated). Captures name, email, optional idea text.
#screen-email
↓ submitEmail()
4
Result
Personalised output. Built by buildResult(tier). Tier: strong / developing / notyet.
#screen-result
State variables: answers {}, currentQ, weightedScore, eacUser, userName, ideaText
Transition: showScreen(id) strips all screens, adds .active.screen--transition to target, scrolls to top.
Auth: Fetched via GET /api/me on load. If present, email screen skipped, isMember:true sent to Airtable.

Patterns

Accessibility

Focus visible ring — Tab to this button:

3px --color-yellow outline, 2px offset. Applies to all button, a, input via :focus-visible.

Reduced motion:

@media (prefers-reduced-motion: reduce) collapses all animation and transition durations to 0.01ms. No behaviour changes — only motion is suppressed.

aria-label usage:

Answer buttons carry aria-label matching their visible text. Score dots container carries aria-label="Your answers".
